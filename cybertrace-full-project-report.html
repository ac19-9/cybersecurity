1. Introduction

CyberTrace is a beginner-friendly, browser-based educational web application that introduces learners to the core concepts and workflows of digital forensics and cybersecurity incident investigation. It simulates a fictional corporate network that has experienced multiple security incidents — giving users a safe, visual, and interactive environment to understand how analysts think and work.

The application is built entirely using front-end web technologies — HTML5, CSS3, and Vanilla JavaScript — with no server, no backend, no database installation, and no external libraries. It runs simply by opening a single HTML file in any modern web browser. No technical setup is required from the user.

A key design principle is transparency: every page prominently displays a disclaimer banner and red "EDUCATIONAL SIMULATION — FICTIONAL DATA ONLY" labels, ensuring learners always understand the context of what they are seeing. All location data has been set to fictional Indian cities to contextualise the simulation for an Indian audience.

7. Suspicious Login Detection System

The Suspicious Login Detector is the most technically detailed feature of CyberTrace. It is split into two parts — a row-level table and an Alerts Panel — each using a different detection approach.

7.1 Part 1 — Row-Level Detection (4 Rules)

Applied per login record in the table. Each row is checked against all 4 rules. A matching row turns red with a badge label.

Rule 1 — Repeated FailuresStatus = "Failed" AND attempt count ≥ 3. Indicates a possible brute-force or password spray attack.
Rule 2 — After HoursLogin hour between 00:00 and 04:59. Logins in this window are statistically unusual for office workers.
Rule 3 — Suspicious LocationLocation = "Unknown" or contains "Tor Network". Tor exit nodes are used to anonymise malicious activity.
Rule 4 — Flagged AccountUsername = phantom_x or unknown_scan. These accounts are known rogue entries identified during investigation.

7.2 Part 2 — Alerts Panel (3 Advanced Pattern Detections)

These three detection functions scan the entire dataset as a whole, looking for patterns that span multiple records — not just one row at a time.

DetectionFunctionAlgorithmSeverity
🔁 Repeated Failed Logins detectRepeatedFailures() Loop through loginAttempts. Flag any record where status = "Failed" AND attempts ≥ 5. Severity is Critical if ≥ 9 attempts. Critical / High
🖥️ Multiple Usernames / One IP detectMultiUserSameIP() Build a Map keyed by IP. For each IP, collect unique usernames in a Set. Flag any IP with Set.size ≥ 2. Critical if ≥ 3 usernames. Critical / High
🔓 Success After Failures detectSuccessAfterFailure() Build a Set of usernames with 3+ prior failures. Find all Success records whose username is in that Set. Every match = Critical alert. Critical

7.4 Toggle-Explanation Feature

Each alert card contains a "💡 What does this mean?" button. Clicking it expands a purple-bordered explanation box written in plain English — suitable for beginners. Clicking again collapses it. This is implemented via the toggleExplanation(idx) function in app.js using element.style.display toggling.

10. SHA-256 Hash Demonstration

The Hash Demo section uses the Web Crypto API — a cryptography engine built into every modern browser — to compute a real SHA-256 hash of any text the user types. No external library is used. The hash updates live as each character is typed.

Code Flow

// Step 1: Encode text to bytes (UTF-8) const data = new TextEncoder().encode(inputText); // Step 2: Compute SHA-256 hash asynchronously const hashBuffer = await crypto.subtle.digest("SHA-256", data); // Step 3: Convert raw bytes to readable hex string const hashHex = Array.from(new Uint8Array(hashBuffer)) .map(b => b.toString(16).padStart(2, "0")).join(""); // Step 4: Display in the output box document.getElementById("hashOutput").textContent = hashHex;

Key Teaching Points Shown in the App

  • SHA-256 always produces a 64-character hex string regardless of input length
  • The avalanche effect: changing even one character completely changes the hash
  • Forensic analysts hash evidence files on collection and verify the hash later to prove no tampering
  • A pre-loaded table shows 5 fictional evidence file names with SHA-256 hashes and forensic notes

15. Conclusion

CyberTrace successfully delivers a beginner-friendly, richly interactive environment for learning digital forensics and cybersecurity concepts — requiring zero installation, zero technical background, and zero cost. By presenting a fictional corporate network incident simulation, the application makes abstract security concepts tangible, visual, and explorable.

The most significant enhancement in the final version is the enhanced Suspicious Login Detector, which goes beyond simple row-level flagging to implement three advanced pattern-detection algorithms — detecting brute-force attacks, credential stuffing (multiple usernames from one IP), and confirmed account compromises (success after failures). All detection data uses fictional Indian city locations, contextualising the simulation for an Indian audience while maintaining complete fictional integrity.

The SHA-256 Hash Demo stands out as a technically genuine feature: it performs a real cryptographic operation using the browser's built-in Web Crypto API, bridging the gap between theory and practice in a completely safe environment. The Forensic Timeline reconstructs three different fictional attack scenarios step-by-step, teaching the investigative narrative approach that real analysts use.

Across 22 educational concepts, 6 fictional case files, 20 login records, 22 system events, 3 timeline cases, and 7 total files — CyberTrace demonstrates how HTML, CSS, and JavaScript alone can be used to build a meaningful, educational, and visually polished application without any external dependencies.

Every element of the application — from the sticky red disclaimer banner to the colour-coded alert severity cards and togglable explanations — is designed with one principle: make cybersecurity accessible, clear, and safe for a complete beginner.
